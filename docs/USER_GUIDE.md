# 黔品智营成品使用说明与CSV体验流程

本说明对应当前本地首版。建议第一次先用模板模式，花约15至25分钟走完“导入、核对、生成、审核、调价、复查、再导出”。模板模式不需要API密钥，输出用于检验业务流程。

体验包中的产品、来源、配料与价格全部拟制。演示设定为：TRY001 V1的正确净含量是200g，初始零售价12元；250g是该版本的误录。实际经营时必须以经营者核对的真实依据取舍。

## 一 打开应用

如果程序正在运行，在这台电脑的浏览器打开 http://127.0.0.1:8501 。打不开时，到项目文件夹双击run.cmd，保持新出现的程序窗口开启，再访问该地址。已完成依赖安装的本机可直接启动；换电脑或解压源码包后，请先按README安装Python3.13与依赖。

页面较窄时左侧导航会折叠，点击左上角的展开箭头，即可看到“产品资料、数据核对、内容工作台、变更追踪”。在侧栏“操作人 / 审核人”填写“体验员”。应用不会自动填入操作人，确认、排除、审核和导出都需要它。

本次使用TRY001、TRY002，不需要清空上一轮P001、P002的记录。体验库有多少历史记录都不影响按SKU选择本次对象。若此前已对TRY001调过价，请看第九部分的独立体验办法。

## 二 先认识四份CSV

| 文件 | 什么时候使用 | 应看到什么 |
| --- | --- | --- |
| 01_首次导入.csv | 第一步，只先上传这一份 | 14条候选，建立TRY001 V1、TRY001 V2、TRY002 V1三个产品对象；TRY001 V1的净含量有冲突 |
| 02_零售价调整为14元.csv | 两份12元文案已审核导出之后 | 只有TRY001 V1的retail价格增加14元候选，人工确认后触发旧内容复查 |
| 03_格式错误体验.csv | 主流程完成后可选体验 | 3条错误行，分别是中文金额、SKU缺失和0g；不会进入有效候选 |
| 04_空白导入模板.csv | 想录入自己的资料时 | 只有表头，需自行补数据；直接上传空模板会提示没有数据行 |

请按顺序分次导入。若生成内容前已将02确认生效，就无法看到“12元旧内容因调成14元而待复查”的这一步。

## 三 导入基础资料

1. 在侧栏点击“产品资料”，停留在“CSV 导入”标签。
2. 点击“Upload”或文件上传区域，选择01_首次导入.csv。这里不要点“导入拟制演示样例”，那个按钮会导入另一组P001样例。
3. 文件编码保持“UTF-8（推荐）”。先看预览：应有14条来源记录、0条格式问题。
4. 点击“确认导入”，看到成功提示后，在侧栏“当前产品对象”选择“TRY001 · V1”。
5. 第一次在没有本组资料的数据库导入，结果为14条候选、0条重复、0条错误。再次上传同一文件并确认，应提示已有相同批次，记录数不再增加。

此时只是保存了资料证据，尚未确认哪些事实正确，不能直接生成含价格的内容。

## 四 处理净含量冲突并确认事实

进入“数据核对”，保持当前对象为TRY001 V1。在“选择待核对字段”选择“净含量（克） · general”。表中能看到三条原文：200g、0.2kg、250g。前两条标准值都是200克，第三条是250克。

先处理错误的250g：

1. 在表中找到原文250g这一行，记住它的“候选编号”。编号来自数据库，不必与截图或其他人的编号相同。
2. 在“选择候选编号”选择这个编号。
3. “处理方式”选择“排除误录”。
4. “核对依据 / 处理原因”填写：“拟制体验设定：本版本包装为200g，250g是误录。”
5. 点击“保存本次处理”。“重新分配的目标产品”只在选择重新分配时使用，这次保持原值即可。

然后确认200g：

1. 如页面自动切换了字段，重新选净含量组。
2. 选择原文200g或0.2kg的候选编号，处理方式务必改回“确认采用”。
3. 原因填写：“拟制体验设定：已核对200g，0.2kg为等价表述。”
4. 点击“保存本次处理”。系统会将两个等价候选都保留为已采纳依据，当前事实只有一项200克。

继续在同一个字段选择框逐项确认以下资料。每项都选该组候选、选择“确认采用”、填写“按拟制体验资料核对无误”，再点保存。

| 页面字段 | 本次确认内容 | 是否必须 |
| --- | --- | --- |
| 产品名称 · general | 体验辣椒酱（拟制） | 必须 |
| 价格（分） · retail | 原文12.00，显示为12.00元 | 本次要生成含价格文案，因此必须 |
| 配料原文 · general | 辣椒、菜籽油、食用盐 | 建议确认，体验完整文案 |
| 使用方法 · general | 可按个人喜好拌饭或佐餐 | 建议确认 |
| 储存说明 · general | 请按包装标示条件保存 | 建议确认 |

通过标准：页面下方“确认事实与来源”能看到产品名称、200克、retail 12.00元和所选说明。必需信息未确认应为0，存在冲突的字段应为0。净含量的确认修订编号和来源均可查看。

## 五 生成两份文案并审核导出

进入“内容工作台”，保持TRY001 V1。

1. 在“生成内容”中选择“商品介绍”。
2. “价格渠道”填写retail，勾选“加入该渠道价格”。这次需要价格进入生成依据，否则后面的调价不会影响这份文案。
3. 说明字段保持需要的勾选，生成方式选择“模板模式（不调用模型）”。
4. 看右侧“本次生成依据”，应包含名称、200克、12.00元及已确认的说明。
5. 点击“生成一份草稿”。点击页面上方“审核与历史”标签，查看新草稿。模板正文可能直接写retail渠道，这是当前渠道标识。
6. 可展开“输入快照、来源与审核记录”，查看这份文案用了哪些字段修订。
7. 点击“提交人工审核”。页面刷新后勾选“已逐句核对名称、规格、价格和其他陈述，未加入无依据事实”。
8. “审核说明”填：“已按本次拟制资料核对，名称、200克和12元一致。”点击“审核通过”。
9. 状态变为“可导出”后，点击“校验依据并下载 TXT”。下载文件含正文、产品对象、修订和审核元信息。
10. 返回“生成内容”，把内容类型改为“朋友圈文案”，仍使用retail、加入价格、模板模式；重复生成、提交审核、审核通过和下载。

通过标准：历史中至少有一份商品介绍和一份朋友圈文案，均为可导出，两份正文都有12.00元。首次生成后内容修订为R1；实际编号以页面为准。

想修改正文时，展开“编辑为新修订”，修改标题或正文并填原因，点击“保存新修订”。这会创建新草稿，需要重新提交审核，原来的审核记录不会自动沿用。若加入新的商品事实，先回资料页补录并确认。

## 六 导入调价文件并查看影响

确认第五部分的两份含12元内容已经完成后，再执行这一步。

1. 回“产品资料 / CSV 导入”，上传02_零售价调整为14元.csv，预览应为1条资料，再点“确认导入”。导入只增加候选，尚未把当前确认价格改为14元。
2. 去“数据核对”，仍选择TRY001 V1，再选择“价格（分） · retail”。页面会显示当前确认12元、新候选14元，提示存在不同值。
3. 选择14.00候选，处理方式选择“确认采用”，填写：“拟制调价单确认：同一版本retail零售价由12元改为14元。”点“保存本次处理”。
4. 这次是用新确认修订替代旧价格；无需删除旧资料，也不要把已经确认的12元当作误录去排除。旧价格保留在历史中。
5. 去“变更追踪”，应看到两份含旧价文案进入“待复查”，触发字段为retail价格，原依据12元，新依据14元。
6. 回“内容工作台 / 审核与历史”查看旧修订：正文仍保留12元，状态为待复查，不能继续正常导出。

通过标准：只改TRY001 V1的retail价格。TRY002 V1、TRY001 V2的事实值不变。若想验证它们的文案也不受影响，应在调价前分别确认其名称、净含量和价格，并各生成、审核一份含价格内容；调价后这些文案仍可导出。

## 七 更新文案并重新导出

1. 在“变更追踪”展开第一份待复查内容，点击“按当前资料生成模板新修订”。这一步确定使用模板，不会请求模型。
2. 回“内容工作台 / 审核与历史”，在“选择内容修订”选新生成的那一份，确认正文已使用14.00元。
3. 再次提交人工审核、逐句核对、填写审核说明、审核通过、下载TXT。
4. 对另一份待复查内容也执行同样操作。
5. 查看历史：原R1保留12元依据，新R2保存14元依据，新修订通过审核后才可导出。

旧修订仍保留待复查标记，这是历史追溯的表现。看“此内容的最新修订”以及内容工作台中最新修订的状态，判断是否已完成本次更新。

本案例旧正文明确写12元，不能直接选择“正文沿用，重绑为新修订”。若要手动处理，应在内容工作台“编辑为新修订”中把正文价格改为14元，填写修改原因并勾选使用当前资料重绑依据，再保存、重审。只有正文经人工核对确实无需修改时，才使用正文沿用功能。

已经下载到电脑、发到朋友圈或贴到商城的旧文件不会被远程改写，需要你自行用新内容替换。

## 八 可选体验错误行与自己的CSV

完成主流程后导入03_格式错误体验.csv。预览中应出现3条格式问题。点击确认导入后，切换到“来源与历史”，选择最新批次，可查看原文和错误原因，并下载错误行清单。这些错误行不形成可确认的产品事实。

自己填写04空白模板时，每行代表一个字段的来源陈述。同一个商品的名称、重量、价格应分成三行，表头不能改成中文。八列含义如下。

| 列名 | 怎么填 |
| --- | --- |
| sku | 稳定商品编号，例如MY001；同名不同规格不要仅凭名称合并 |
| product_version | 产品版本，例如V1；真实换包装可另建V2 |
| field_key | 固定六选一：product_name、net_weight_g、price_cent、ingredients_text、usage_text、storage_text |
| raw_value | 来源原文；重量200g或0.2kg；价格按元填12.00，虽然字段名含cent，也不要填1200来表示12元 |
| context_key | 价格填明确渠道retail或wholesale；其余字段填general |
| source_label | 来源名称，例如已核对包装、零售价表 |
| source_locator | 来源位置，例如第2行、标签正面；不要用它冒充真实来源 |
| effective_from | YYYY-MM-DD，可空；未来日期的资料先留候选，不提前确认生效 |

使用Excel或WPS另存为CSV UTF-8格式，保留八列表头。相同价格渠道名称要完全一致。当前最多上传5MB；只支持CSV，不直接上传xlsx、PDF或Word。

## 九 常见问题

| 遇到的情况 | 处理方法 |
| --- | --- |
| 保存时提示操作人或原因为空 | 在侧栏填操作人，在当前表单填写原因，重新提交 |
| 确认200g时提示仍有不同值 | 先排除本次误录250g，再回200g组选择确认采用；200g和0.2kg无需互相排除 |
| 生成按钮不可用 | 检查名称、净含量是否已确认；勾选价格时retail价格也要确认；处理所选字段冲突；第一次使用模板模式 |
| 页面出现的是P001而不是TRY001 | 在侧栏当前产品对象选择TRY001 V1；本次手动上传01，不点内置样例导入按钮 |
| 看不到新生成或更新的内容 | 切换到审核与历史，并在内容修订下拉框选择最新编号或R2 |
| 导入同一文件没有新增记录 | 正常现象，系统按文件哈希识别相同批次 |
| 调价后没有提醒 | 检查两份内容是否在调价前生成、是否勾选加入价格、渠道是否均为retail，以及是否已人工确认14元候选 |
| 导入02后暂时不能导出旧内容 | 新候选与旧确认值存在冲突，需先完成人工取舍，随后更新并重审相关内容 |
| 更新后仍看到旧内容待复查 | 旧修订保留历史标记，查看最新R2是否已审核可导出 |
| 真实模型选项无法用 | 本地配置DeepSeek API Key后使用；本体验流程无需密钥，不会调用真实模型 |
| 上传乱码 | 优先选择UTF-8；确为旧编码时明确改为GB18030后重新预览 |

如果想从头再做一轮，不删除已有数据库。在项目文件夹空白处打开PowerShell，运行下面两行，启动一个独立体验目录与8502端口。若目录已存在，会接着使用该目录的历史；想再次从零开始就换一个尚未使用的目录名。

```powershell
$env:QIANPIN_RUNTIME_DIR = "$PWD/runtime/walkthrough-new"
.\.venv\Scripts\python.exe -m streamlit run app.py --server.address=127.0.0.1 --server.port=8502
```

浏览器打开 http://127.0.0.1:8502 ，从上传01重新开始。原8501窗口的数据保留。结束时在启动它的终端按Ctrl+C。这个方法不需要运行自动演示脚本，可以保留每一步由你亲自操作的体验。

## 十 体验完成核对

- 能看到原始资料、原文、候选和人工取舍原因。
- 200g与0.2kg归为同值，250g误录由人明确排除。
- 两类内容均经过草稿、待审核、可导出三个步骤。
- 价格12元改14元后，两份旧内容被追踪并停止正常导出。
- 新修订使用14元、重新审核，旧正文与旧依据仍能查到。
- 没有修改另一SKU或另一产品版本的事实。

完成这些动作，就体验了当前首版最核心的数据治理与内容维护流程。
