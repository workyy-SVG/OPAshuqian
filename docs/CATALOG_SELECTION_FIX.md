# 商品选择与候选预览修复

## 修复的问题

旧版卡片按钮把选中商品写入会话后，候选预览渲染在所有商品卡片和分页控件下方；12项商品时距离较远，点击后缺乏就近反馈，看起来像“点不动”。原有自动化只检查可导入，没有验证预览的可见性。

现在卡片按钮直接打开“商品候选预览”弹窗，展示名称、条码、来源、规格、缺失字段和导入表单。关闭弹窗不会导入；可以重新打开或选择另一商品；成功导入后弹窗关闭并选中目标SKU。卡片预览不再额外请求上游。

牛奶“450 ml”等体积规格明确提示不能直接当作克重；可导入已有名称和配料，重量需另行核实补录。不会为了通过导入而编造重量。

## 不知道条码或名称时

两个入口均可使用真实分类接口提供的商品列表：

1. 在“按分类挑选商品”中选分类并点击“浏览这个分类”，直接从本页下拉列表或卡片选择商品。
2. 在“条码 / 名称查询”中默认选择“从商品列表选择（无需输入）”，选分类、加载可选商品、选择并预览。

乳品增加牛奶、酸奶、奶酪细分类。下拉框可按本页已加载的名称筛选，不代表已搜索整个数据库。找不到时可翻页、换分类或使用名称关键词查询。条码与名称分别保留输入内容，避免切换名称后误用原条码。

使用现有Open Food Facts公开接口，不需要新增API密钥；分类是远程数据库的分类，可能误分、缺少中文名称或资料不完整，不等于商家库存。没有抓取或复制全库，也没有在生产页面放入模拟商品作为真实商品。

## 接口失败时

503表示上游暂时无法提供响应，不能靠界面改动保证它不再发生。错误提示与“成功查询但没有商品”分开；失败时可以重试或切换列表模式。分类翻页失败保留上一次成功页及正确页码，已有卡片仍可预览。首次加载也失败时，CSV与手工补录仍可用。

## 验证

- 115项测试通过，核心覆盖率93.22%，类型检查与编译检查通过。
- 新增/强化测试覆盖卡片打开、下拉选择、牛奶体积提示、关闭重开、换商品后导入、成功后关闭、503保留上一页，以及不把503显示为无搜索结果。
- 实际Chromium浏览器在1440×1000和390×844下加载12张卡片，点击卡片打开弹窗，通过列表选另一商品并完成导入；弹窗未超出视口。
- 浏览器及接口回归测试使用明确的模拟响应，仅证明应用交互，不证明当前公网Open Food Facts可用。截图与记录保存在忽略目录 `runtime/catalog-validation/evidence/`。

运行：`.venv/bin/python -m pytest tests/test_catalog.py tests/test_food_facts.py -q`。完整验收仍使用README的测试命令。公开站点需要部署本次提交后才能出现新弹窗和列表入口。
